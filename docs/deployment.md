# Развёртывание на Astra Linux (пошагово)

## 0. Что получится

Каталог `translator-bundle-<дата>/` со структурой:

```
translator-bundle-<дата>/
├── start.sh          # запуск: bash start.sh (исполняемый бит не требуется)
├── selftest.sh       # самопроверка на целевой машине: bash selftest.sh
├── python/           # портативный CPython 3.11 (linux x86_64)
├── site-packages/    # зависимости (faster-whisper, ctranslate2, fastapi, …)
├── models/           # whisper-large-v3, whisper-medium, whisper-small, nllb-600m-ct2
├── app/  web/        # код сервиса и интерфейс
├── output/ work/ logs/ testdata/
└── requirements.txt
```

Системный Python на целевой машине не используется; ничего на компьютер не
устанавливается; запись — только в подкаталоги бандла (и `/tmp` при noexec).

## 1. Сборка (машина с интернетом)

```bash
# разовая подготовка моделей, если ещё не сделана:
uv pip install -r requirements-convert.txt -p .venv
.venv/bin/python scripts/prepare-models.py

# сборка и упаковка:
bash scripts/build-offline-bundle.sh
```

Результат: `translator-bundle-<дата>.tar.gz` (~8 ГБ: large-v3 ~3 ГБ,
medium ~3 ГБ, small ~0.5 ГБ, nllb int8 ~0.7 ГБ, python+site-packages ~0.5 ГБ).

## 2. Перенос на флешку

Рекомендуется **ext4** (нативна для Linux, права и симлинки работают как есть):

```bash
# на машине с флешкой (осторожно: сотрёт данные!):
diskutil list                                   # найти диск флешки
sudo mkfs.ext4 /dev/sdX                         # на Linux
rsync -av translator-bundle-<дата>/ /media/usb/translator/
```

exFAT/FAT32 тоже работают: сборка без симлинков (pip --target), файлы моделей
меньше 4 ГБ (лимит FAT32 на файл). При распаковке tar на FAT32 возможны
предупреждения о симлинках и правах — они не влияют на запуск (start.sh
использует `python/bin/python3.11` напрямую).

## 3. Проверка на целевой машине Astra

```bash
cd /media/<флешка>/translator-bundle-<дата>
bash selftest.sh
```

Ожидаемый вывод: `PASS: бандл работает офлайн.` Скрипт поднимает сервис на
порту 8099, отправляет тестовый клип (small-модель), дожидается готовности и
проверяет три файла результата. Интернет машине не нужен — по определению.

## 4. Штатная работа

```bash
bash start.sh                                   # localhost:8080
HOST=0.0.0.0 bash start.sh                      # доступ из локальной сети
PORT=8081 bash start.sh                         # другой порт
```

В браузере: загрузка аудио (mp3/m4a/wav/ogg/flac/mp4, до 2 ГБ), выбор языка
(узбекский/азербайджанский/таджикский/авто) и модели, прогресс, результат —
расшифровка и перевод на странице + скачивание transcript.txt,
translation.txt, result.docx.

## 5. Известные ограничения

- **noexec-монтирование** съёмных носителей: start.sh обнаруживает это и
  копирует бинарник python в `/tmp` (нужно ~100 МБ в /tmp). Если и это
  запрещено — переносить бандл на локальный диск (`cp -r`, ~7 ГБ) и запускать
  оттуда; установка в систему всё равно не требуется.
- **PARSEC (Astra SE)**: если съёмные носители запрещены политиками мандатного
  контроля — вопрос к администраторам; из ПО это не решается.
- **Память**: модель large-v3 (int8) + переводчик занимают ~3–3.5 ГБ; при 8 ГБ RAM
  одновременно обрабатывается одна задача (так и задумано).
- **Качество**: uz/az/tg — низкоресурсные языки; оценка WER на FLEURS —
  в `docs/benchmark.md`; на записях плохого качества ожидайте заметные ошибки.

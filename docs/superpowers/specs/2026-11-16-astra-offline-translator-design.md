# Дизайн: офлайн-сервис расшифровки аудио с переводом на русский

Дата: 2026-11-16
Статус: одобрен пользователем (устно, в диалоге)

## 1. Цель и сценарий

Программа расшифровки аудиозаписей на узбекском, таджикском и азербайджанском
языках с переводом расшифровки на русский язык.

Условия эксплуатации:
- ОС: Astra Linux, x86_64. **Интернета нет** — ни при установке, ни при работе.
- Железо: обычный ПК, оперативной памяти не больше 8 ГБ, GPU нет (CPU-only).
- Объём: единичные файлы (минуты — десятки минут), скорость некритична.
- Развёртывание: **полностью портативное** — комплект на флешке, запуск с флешки,
  без установки на компьютер. Снял флешку — деинсталляция завершена.
- Интерфейс: локальный веб-интерфейс (страница в браузере внутри закрытой сети).

## 2. Основание выбора моделей (проверенные факты)

- Whisper (OpenAI) поддерживает все три языка: в списке токенизатора есть
  `"tg": "tajik"`, `"uz": "uzbek"`, `"az": "azerbaijani"` —
  https://github.com/openai/whisper (whisper/tokenizer.py).
- Vosk отклонён как единое решение: узбекский есть
  (vosk-model-small-uz-0.22), таджикский есть, но плохой (WER 38–41%),
  азербайджанского нет — https://alphacephei.com/vosk/models.
- Перевод: NLLB-200 покрывает прямые пары в русский — `uzn_Latn`, `azj_Latn`,
  `tgk_Cyrl` → `rus_Cyrl` (FLORES-200 коды; dl-translate
  https://dl-translate.readthedocs.io/en/latest/available_languages).
- OPUS-MT: прямых моделей uz/az/tg→ru не существует (страницы
  `Helsinki-NLP/opus-mt-uz-ru`, `-az-ru`, `-tg-ru` на Hugging Face дают 404).
- SeamlessM4T v2 отклонён: тяжёлый стек fairseq2 (проблемно собрать офлайн),
  входное покрытие речью для az/tg не гарантировано, ASR-качество на
  низкоресурсных языках ниже, чем у Whisper large.

Итог: **Whisper для расшифровки + NLLB-200 для перевода**, всё на CPU.

## 3. Архитектура

Один Python-сервис (FastAPI + uvicorn):
- Локальный веб-интерфейс — одна страница (HTML/CSS/JS без сборочных тулзов).
- Задачи обрабатываются последовательно из очереди (threading); модели
  загружаются лениво, по требованию.
- Пиковая память ~3 ГБ (при последовательной работе ASR и переводчика) —
  укладывается в 8 ГБ с учётом ОС.
- Порт по умолчанию 8080, настраивается (аргумент запуска / конфиг).

## 4. Компоненты

1. **Расшифровка — faster-whisper** (CTranslate2):
   - Модель по умолчанию: `large-v3-turbo` (int8, ~0.8 ГБ) — оптимум
     качество/скорость для слабого CPU.
   - Переключатель модели в UI: `large-v3-turbo` / `medium` / `small`
     (medium и small быстрее в 2–4 раза, качество ниже).
   - Язык выбирается в UI: узбекский / таджикский / азербайджанский / авто.
     Ручной выбор по умолчанию: автодетект между uz/az/tg ненадёжен.
   - VAD-фильтр (silero, входит в faster-whisper) включён — чанкинг длинных
     записей.
   - Расшифровка сохраняется вместе с таймкодами сегментов.
2. **Перевод — NLLB-200-distilled-600M** (int8, через CTranslate2):
   - Маппинг кодов: uz→`uzn_Latn`, az→`azj_Latn`, tg→`tgk_Cyrl`, выход
     `rus_Cyrl`.
   - Перевод посегментно/небольшими батчами.
   - Запасной путь повышения качества: NLLB-1.3B (RAM позволяет, ~1 ГБ int8);
     в базовую сборку не входит, подключается как опция.
3. **Декодирование аудио — PyAV** (FFmpeg-библиотеки в комплекте
   faster-whisper): mp3, m4a, wav, ogg, flac, аудиодорожка mp4. Системный
   ffmpeg не требуется.
4. **Результаты** — каталог `output/<метка времени>_<имя файла>/`:
   - `transcript.txt` — расшифровка на исходном языке (с таймкодами);
   - `translation.txt` — перевод на русский (с таймкодами);
   - `result.docx` — оба текста одним документом (python-docx).

## 5. Поток данных

Загрузка аудио через веб-форму → файл сохраняется в рабочий каталог на флешке →
фоновая задача: декодирование и ASR (прогресс по сегментам) → перевод сегментов
→ запись результатов → статус в UI: «загружаю модель…» / «расшифровка N%» /
«перевод» / «готово» + ссылки на скачивание. Статусы задач хранятся в памяти
сервиса и дублируются JSON-файлом в каталоге задачи.

## 6. Портативное развёртывание

Флешка (рекомендуется **ext4**; поддерживается exFAT/FAT32 — сборка без
симлинков и без файлов >4 ГБ).

```
translator/
├── start.sh          # запуск: bash start.sh (исполняемый бит не требуется)
├── python/           # портативный CPython 3.11 (python-build-standalone)
├── site-packages/    # зависимости: pip install --target (пути не зашиты)
├── models/           # whisper (faster-whisper CT2) + NLLB (CT2)
├── app/              # код сервиса
├── output/           # результаты
├── work/             # временные файлы обработки
└── logs/
```

- Запуск: `bash start.sh` → сервис на `localhost:8080`, открывается в браузере.
- start.sh самопозиционируется (`dirname "$0"`), выставляет PYTHONPATH;
  при `noexec`-монтировании — копирует бинарник python в `/tmp` и запускает
  оттуда (остальные компоненты исполняемые биты не используют).
- Сборка комплекта — отдельным скриптом `build-offline-bundle.sh` на машине
  с интернетом: скачивает портативный CPython, ставит зависимости в
  site-packages, скачивает модели с Hugging Face, упаковывает всё в тарболл.
- На хост ничего не устанавливается; запись — только в каталоги на флешке
  (и `/tmp` в fallback-сценарии noexec).
- Переменная окружения `HF_HUB_OFFLINE=1` и локальные пути моделей — чтобы
  библиотеки не пытались лезть в сеть.

## 7. Обработка ошибок

- Неподдерживаемый или повреждённый файл → понятное сообщение в UI.
- Ошибка загрузки модели / нехватка памяти → сообщение в UI, задача
  помечается как неудачная, сервис продолжает работу.
- Ошибка перевода отдельного сегмента → сегмент помечается в результате
  (пустой перевод с пометкой), остальные сегменты обрабатываются.
- Файлы неподходящего размера (пустой, >2 ГБ) → отказ с сообщением.
- Никаких внешних сетевых вызовов — проверяется в сборке (оффлайн-тест).

## 8. Тестирование

- Реальные образцы аудио от пользователя: по 1–2 файла на каждый язык
  (uz, az, tg) — получить до написания кода.
- Сравнение `large-v3-turbo` / `medium` / `small` на образцах: субъективное
  качество + время + потребление памяти.
- Проверка сборки и запуска: ext4-флешка, exFAT-вариант, имитация `noexec`.
- Оффлайн-проверка: запуск с отключённой сетью (интерфейс lo) — сервис
  работает, внешних соединений нет.
- Приёмочный критерий: на целевой машине Astra пользователь получает
  расшифровку и перевод единичного файла, не установив ничего на компьютер.

## 9. Ограничения и риски

- uz/az/tg — низкоресурсные языки для Whisper: расшифровка будет с ошибками,
  особенно на записях плохого качества. Валидировать на реальных образцах;
  при недостаточном качестве — этап 2: дообучение Whisper на корпусах
  (Common Voice uz/az, таджикские данные) и/или NLLB-1.3B.
- Скорость на слабом CPU: ~10-минутный файл моделью `large-v3-turbo`
  ориентировочно 20–40 минут; medium/small — в 2–4 раза быстрее.
- Политики Astra SE (PARSEC) в отношении съёмных носителей и noexec — вне
  зоны решения; при полном запрете съёмных носителей нужен другой способ
  доставки (вопрос к администраторам сети).
- Оценки времени/памяти — ориентировочные, до тестов на целевой машине.
